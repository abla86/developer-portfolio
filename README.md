## Evidence standard

The portfolio distinguishes:

**prototype → demonstration → verified → production-ready**

A repository is not described as production-ready merely because it builds or looks complete.

Where appropriate, the portfolio uses:

- source inspection
- automated tests
- CI
- linting and static analysis
- dependency/security controls
- documentation
- explicit architecture boundaries
- reproducible demonstrations
- live deployment verification where deployment exists

For research-support software, **software correctness is kept separate from scientific or methodological validity**. The application can automate a workflow, but scientific interpretation remains the responsibility of qualified users.

## Skill integration rule

A technology from a job description is integrated into the repository where it has a legitimate architectural purpose. If integration would be artificial, it is kept as a bounded demonstration or explicitly marked as a future target.

The current mapping is maintained in `AB-Engineering-Lab/docs/SKILL-INTEGRATION-MATRIX-2026-09.md` and surfaced interactively through `stack.html`.

## Interactive layer

The portfolio is not intended to be a collection of static project cards. Public pages expose bounded interaction: filtering, search, inspection panels, simulations, visualizations, games and research/security workflow controls.

The interactive layer demonstrates implementation concepts; the GitHub repositories remain the authoritative implementation evidence.

## Project maturity

Historical, training, archived and supporting repositories may remain visible on GitHub without being promoted as flagship products.

That distinction is intentional.

A project earns a primary position when there is enough:

1. implemented functionality
2. public inspectability
3. verification evidence
4. documentation
5. distinct technical value

to justify the claim.

## Engineering principle

> **Build → test → secure → document → validate.**

The objective is a portfolio that can be inspected by a technical reviewer rather than a collection of technology keywords.
