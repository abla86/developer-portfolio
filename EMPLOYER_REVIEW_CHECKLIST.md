# Employer / Recruiter Review Checklist

Use this checklist before adding a project or capability to the public portfolio.

## Project evidence

- [ ] Problem/purpose is stated clearly.
- [ ] Implemented scope is distinguishable from planned scope.
- [ ] Technologies listed are actually present in the repository.
- [ ] Current status is explicitly labelled.
- [ ] Tests or other verification are described only when evidence exists.
- [ ] CI/security tooling is described only when configured.
- [ ] Live demos are labelled as demo/prototype where appropriate.
- [ ] README provides setup and usage information appropriate to the project.
- [ ] Source repository is linked.

## Claim control

- [ ] No completed degree is implied where education is ongoing.
- [ ] No clinical/scientific validation is implied by software implementation.
- [ ] No certification is implied by portfolio achievements.
- [ ] No technology is claimed solely because it appears in a generic skills list.
- [ ] No placeholder, TODO, TBD or invented result is presented as completed work.

## Employer-facing priority

The first information a recruiter should see is:

1. what was built;
2. why it matters;
3. evidence that it works or has been verified;
4. current maturity/status;
5. source/documentation.

Small learning projects remain available as progression evidence but do not receive the same visual weight as the main engineering projects.
